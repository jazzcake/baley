# Bird View 개발 중단 결정

- 결정일: 2026-09-08
- 상태: 일시 중단
- 대상 branch: `jazzcake/bird-view-nodes`
- 중단 직전 구현 commit: `59d833d9905abf477d743139656ce49318504c5b`

## 결정

Bird View 개발을 현재 지점에서 멈춘다. 구현 결과는 원격 feature branch에 보존하지만 운영 branch로 병합하거나 배포하지 않는다.

이번 중단은 기술적 검증 실패 때문이 아니라 제품 효용과 개발 우선순위에 대한 판단이다.

## 이유 1: 현재 Bird View의 효용 부족

현재 구현은 자유로운 BV Node graph, 같은 canvas의 focus 전환, 관련 Phase/Gate/Task subset, 곡선 edge와 편집 기능까지 기술적으로 검증됐다. 그러나 이 경험이 기존 Baley 흐름보다 사용자의 판단과 실행을 충분히 개선하는지는 아직 명확하지 않다.

따라서 현재 효용이 추가 개발 비용을 정당화한다고 보기 어렵다. 기능 범위를 더 넓히기 전에 Bird View만이 해결할 수 있는 구체적인 사용자 문제와 측정 가능한 효과를 다시 확인해야 한다.

## 이유 2: 개발 의사결정 기록 보전이 더 시급함

현재 더 중요한 문제는 모든 개발 의사결정의 맥락과 근거가 세션, Task, Run, worktree 및 commit 경계를 넘어 보전되는 것이다. 무엇을 만들었는지만이 아니라 다음 정보가 복구 가능해야 한다.

- 어떤 문제와 제약 때문에 결정을 내렸는가
- 어떤 대안이 검토됐고 왜 선택하거나 제외했는가
- 결정이 어떤 Task, Run, Record, evidence 및 commit으로 이어졌는가
- 이후 상황이 바뀌었을 때 무엇을 재검토해야 하는가

이 기반이 약한 상태에서 Bird View를 계속 확장하면 시각화할 대상인 개발 맥락 자체가 불완전해진다. 따라서 Bird View 고도화보다 개발 의사결정 기록의 수집, 연결, 검색, 복구 체계를 우선한다.

## 보존 상태

- Bird View 구현과 검증 기록은 `jazzcake/bird-view-nodes` 원격 branch에 보존한다.
- 관련 Baley Task #172~#179와 Task Record는 구현 commit 및 blob evidence에 연결돼 있다.
- DayTripper용 격리 데이터베이스와 Tailscale serve 매핑은 삭제하지 않았지만, 이를 실행 중인 서비스로 간주하지 않는다.
- 운영 branch 병합, 배포, 운영 데이터베이스 변경 및 사람 확인은 수행하지 않았다.

## 재개 조건

다음 조건이 갖춰진 뒤 Bird View의 현재 설계를 그대로 이어갈지부터 다시 판단한다.

1. 개발 의사결정 기록 보전의 최소 기준과 복구 흐름이 먼저 마련될 것
2. Bird View가 해결할 구체적인 사용자 의사결정 문제와 성공 기준이 정의될 것
3. 기존 Baley 화면보다 나은 효과를 실제 사용 흐름에서 검증할 방법이 있을 것
4. 현재 branch의 데이터 모델과 UI를 전제로 두지 않고 대안까지 재평가할 것
